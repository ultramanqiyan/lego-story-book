## 一、苏格拉底式提问与回答（30问）

### 1.1 关于架构设计（10问）

**Q1：为什么选择无服务器架构？**

**回答**：选择无服务器架构的原因：
1. **零运维成本**：无需管理服务器、操作系统、运行环境
2. **自动扩展**：请求量增加时自动扩展，无需手动配置
3. **按需付费**：只对实际使用的请求付费，空闲时不产生费用
4. **快速部署**：代码提交后自动部署，无需手动发布流程
5. **全球分布**：Cloudflare在全球300+城市有节点，用户就近访问

**实际成本**：免费套餐每月100,000次请求，对于小型项目完全够用。

**Q2：为什么选择Cloudflare Pages而不是其他平台？**

**回答**：选择Cloudflare Pages的原因：

| 平台 | 优点 | 缺点 |
|------|------|------|
| Cloudflare Pages | 全球CDN、D1数据库集成、免费额度高 | Functions有执行时间限制 |
| Vercel | 部署简单、预览功能好 | 数据库需要额外配置 |
| Netlify | 功能丰富、插件生态好 | 免费额度较低 |
| AWS Amplify | AWS生态集成好 | 配置复杂、成本高 |

**最终选择**：Cloudflare Pages + D1数据库的组合，提供了一体化的解决方案，且免费额度足够小型项目使用。

**Q3：边缘计算对性能有什么影响？**

**回答**：边缘计算的性能影响：

**正面影响**：
- 首字节时间（TTFB）降低50%-80%
- 静态资源从最近节点加载
- API请求延迟降低

**实际测试数据**：
```
美国用户访问：TTFB ~50ms
中国用户访问：TTFB ~150ms（需要经过更多节点）
欧洲用户访问：TTFB ~60ms
```

**负面影响**：
- 数据库查询需要从边缘节点到中心数据库
- AI API调用不受边缘计算影响（取决于AI服务响应时间）

**Q4：系统如何处理高并发？**

**回答**：高并发处理机制：

1. **Cloudflare自动扩展**：每个请求独立处理，自动分配计算资源
2. **无状态设计**：不依赖服务器内存状态，每个请求独立
3. **数据库连接池**：D1自动管理数据库连接
4. **CDN缓存**：静态资源缓存在边缘节点

**限制因素**：
- D1数据库有并发连接限制
- AI API有速率限制
- 单个Function执行时间限制（免费版10ms CPU时间）

**Q5：系统如何保证高可用？**

**回答**：高可用保障措施：

| 层面 | 措施 | SLA |
|------|------|-----|
| 网络 | Cloudflare全球网络 | 99.99% |
| 计算 | 自动故障转移 | 99.99% |
| 存储 | D1自动备份 | 99.9% |
| 代码 | GitHub版本控制 | - |

**实际可用性**：自项目部署以来，未发生过服务中断。

**Q6：系统有哪些单点故障风险？**

**回答**：单点故障风险分析：

| 风险点 | 影响 | 缓解措施 |
|--------|------|----------|
| 豆包API不可用 | 无法生成故事 | 显示错误提示，用户可重试 |
| D1数据库不可用 | 所有功能不可用 | Cloudflare自动故障转移 |
| Cloudflare服务中断 | 整站不可用 | 等待Cloudflare恢复 |
| GitHub仓库不可用 | 无法部署新版本 | 不影响已部署版本 |

**最大风险**：豆包API的可用性，因为这是第三方服务，我们无法控制。

**Q7：系统如何扩展？**

**回答**：系统扩展方式：

**垂直扩展**（增加单个资源能力）：
- Cloudflare自动处理，无需手动配置
- D1数据库存储空间可扩展

**水平扩展**（增加资源数量）：
- Cloudflare自动扩展Functions实例
- 无需修改代码

**功能扩展**：
- 添加新的API端点（functions/api/目录下添加新文件）
- 添加新的前端页面（添加新HTML文件）

**Q8：前后端分离的程度如何？**

**回答**：前后端分离程度：

| 方面 | 分离程度 | 说明 |
|------|----------|------|
| 代码仓库 | 完全分离 | 前端HTML和后端JS在同一仓库但不同目录 |
| 部署 | 统一部署 | 前端和后端一起部署到Cloudflare Pages |
| 通信 | HTTP API | 前端通过fetch调用后端API |
| 认证 | 无状态 | 前端存储用户ID，后端每次验证 |

**特点**：不是完全分离的SPA架构，而是传统的多页面应用（MPA）+ API架构。

**Q9：静态资源和动态请求如何区分处理？**

**回答**：请求处理方式：

| 资源类型 | 处理方式 | 缓存策略 |
|----------|----------|----------|
| HTML文件 | 直接返回 | 不缓存（或短缓存） |
| CSS/JS/图片 | 直接返回 | 长期缓存 |
| /api/*请求 | Functions处理 | 不缓存 |

**Cloudflare配置**：
```toml
# wrangler.toml
pages_build_output_dir = "."
```

所有非API请求直接返回静态文件，API请求由Functions处理。

**Q10：CDN缓存策略是什么？**

**回答**：CDN缓存策略：

**静态资源**：
- HTML文件：Cache-Control: no-cache（每次验证）
- CSS/JS文件：Cache-Control: max-age=31536000（一年）
- 图片文件：Cache-Control: max-age=86400（一天）

**API响应**：
- 默认不缓存
- 可通过响应头设置缓存策略

**实际配置**：
```javascript
// 在API响应中设置
headers: {
  'Cache-Control': 'no-store'
}
```

  ↓ 1:N

**Q17：为什么使用文本类型的主键？**

**回答**：使用文本主键的原因：

1. **分布式友好**：不需要中央ID生成器
2. **可读性**：ID格式为`id_xxx_xxx`，便于调试
3. **无冲突**：时间戳+随机数，冲突概率极低

**ID生成函数**：
```javascript
export function generateId() {
  return 'id_' + Date.now().toString(36) + '_' + Math.random().toString(36).substr(2, 9);
}
```

**示例ID**：`id_m1a2b3c_d4e5f6g7h`

### 1.5 关于安全性（5问）

**Q26：系统如何防止SQL注入？**

**回答**：SQL注入防护：

**使用参数化查询**：
```javascript
// 安全的方式
await DB.prepare('SELECT * FROM users WHERE user_id = ?')
  .bind(userId).first();

// 不安全的方式（不要使用）
await DB.prepare(`SELECT * FROM users WHERE user_id = '${userId}'`).first();
```

**所有数据库操作都使用参数化查询**，不拼接SQL字符串。

**Q27：系统如何防止XSS攻击？**

**回答**：XSS防护措施：

1. **输入验证**：限制输入长度和字符
2. **输出编码**：使用textContent而非innerHTML
3. **CSP头**：设置内容安全策略

**代码示例**：
```javascript
// 安全的方式
element.textContent = userInput;

// 不安全的方式
element.innerHTML = userInput;
```

**Q28：用户数据如何隔离？**

**回答**：数据隔离机制：

1. **查询过滤**：所有查询都带user_id条件
```javascript
const books = await DB.prepare(
  'SELECT * FROM books WHERE user_id = ? AND status = ?'
).bind(userId, 'active').all();
```

2. **角色隔离**：用户只能访问自己创建的角色和系统预设角色
```javascript
const characters = await DB.prepare(
  'SELECT * FROM characters WHERE creator_id = ? OR creator_id = ?'
).bind(userId, 'system').all();
```

**Q29：敏感信息如何保护？**

**回答**：敏感信息保护：

| 信息类型 | 存储位置 | 保护方式 |
|----------|----------|----------|
| API密钥 | Cloudflare环境变量 | 不在代码中暴露 |
| 用户ID | 浏览器localStorage | 随机字符串 |
| 用户名 | 数据库 | 无密码存储 |

**环境变量配置**：
```javascript
const apiKey = context.env.DOUBAO_API_KEY;
```

**Q30：API密钥如何管理？**

**回答**：API密钥管理：

1. **存储位置**：Cloudflare Pages环境变量
2. **访问方式**：通过context.env访问
3. **更新方式**：在Cloudflare Dashboard更新
4. **版本控制**：不在代码仓库中存储

**配置步骤**：
1. 进入Cloudflare Dashboard
2. 选择项目 > Settings > Environment variables
3. 添加变量名和值
4. 重新部署生效
