## 一、接口概述

### 1.1 接口规范

乐高故事书系统的API接口遵循RESTful设计规范，提供简洁、一致、易于理解的接口风格。

**基础URL**是所有API接口的公共前缀。在开发环境中，基础URL为本地服务器地址加API路径。在生产环境中，基础URL为部署域名加API路径。所有接口请求都需要使用HTTPS协议，确保数据传输安全。

**请求方法**遵循HTTP标准方法的语义。GET方法用于获取资源，不修改服务器状态。POST方法用于创建资源或执行操作。PUT方法用于更新资源。DELETE方法用于删除资源。每个接口只使用一种请求方法，确保语义清晰。

**请求格式**统一使用JSON格式。请求体中的数据使用JSON编码，请求头中需要设置内容类型为JSON类型。对于GET请求，参数通过URL查询字符串传递。对于POST、PUT、DELETE请求，参数通过请求体传递。

**响应格式**统一使用JSON格式。响应体中包含状态码、数据和消息字段。状态码表示请求处理结果，数据字段包含返回的数据，消息字段包含提示信息。所有响应使用UTF-8编码，支持中文内容。

**字符编码**统一使用UTF-8编码。请求和响应中的所有文本数据都使用UTF-8编码，确保中文字符正确显示。

### 1.2 认证方式

系统采用基于用户ID的认证方式，通过会话管理实现用户身份验证。

**会话创建**发生在用户登录时。用户登录成功后，系统创建会话，生成用户ID标识。会话信息存储在浏览器本地存储中，包含用户ID和过期时间。

**会话传递**通过请求参数实现。每次API请求时，前端从本地存储获取用户ID，添加到请求参数中。后端从请求参数获取用户ID，验证用户身份。

**会话验证**在每次请求时执行。后端接收请求后，从请求参数获取用户ID，查询数据库验证用户是否存在。如果用户不存在，返回未认证错误。

**会话过期**由本地存储管理。会话信息存储在浏览器本地存储中，用户可以手动清除。系统不强制设置会话过期时间，由用户自行管理登录状态。

### 1.3 错误处理

系统定义了统一的错误处理机制，确保错误信息的一致性和可理解性。

**错误响应格式**包含错误码和错误消息。错误码是数字类型的标识符，用于程序识别错误类型。错误消息是文本类型的描述，用于人类理解错误原因。

**常见错误码**包括以下类型：参数错误表示请求参数无效或缺失；未认证错误表示用户未登录或会话过期；权限错误表示用户无权访问请求的资源；资源不存在错误表示请求的资源不存在；服务器错误表示服务器内部发生错误。

**错误处理建议**包括以下方面：前端需要捕获所有API错误，显示友好的错误提示；后端需要记录所有错误日志，便于问题排查；测试需要覆盖所有错误场景，确保错误处理正确。

### 1.4 通用参数

部分参数在多个接口中通用，具有相同的含义和用法。

**用户ID参数**用于标识当前用户，在需要认证的接口中必须传递。该参数通过URL查询字符串传递，参数名为userId。参数值为用户的唯一标识符，由系统在用户注册时生成。

**书籍ID参数**用于标识书籍资源，在书籍相关接口中传递。该参数通过URL查询字符串或请求体传递，参数名为bookId或id。参数值为书籍的唯一标识符，由系统在创建书籍时生成。

**章节ID参数**用于标识章节资源，在章节相关接口中传递。该参数通过URL查询字符串或请求体传递，参数名为chapterId或id。参数值为章节的唯一标识符，由系统在创建章节时生成。

**分页参数**用于分页查询接口。页码参数名为page，默认值为第一页。每页数量参数名为limit，默认值为二十条。

## 二、用户接口

### 2.1 用户注册接口

**接口描述**：创建新的用户账户，注册成功后自动创建会话。

**请求路径**：/api/users

**请求方法**：POST

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| action | 字符串 | 是 | 操作类型，值为register |
| username | 字符串 | 是 | 用户名，长度二到二十个字符 |
| password | 字符串 | 是 | 密码，长度六到五十个字符 |

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| success | 布尔值 | 是否成功 |
| user | 对象 | 用户信息，包含用户ID、用户名等 |
| message | 字符串 | 提示信息 |

**成功响应示例**：

请求成功时，返回状态码为成功，用户对象包含新创建的用户信息，包括用户ID和用户名。消息字段提示注册成功。

**失败响应示例**：

用户名已存在时，返回状态码为失败，消息字段提示用户名已被使用。参数无效时，返回状态码为失败，消息字段提示具体的参数错误。

**业务规则**：

用户名必须唯一，不能与已注册用户重复。用户名长度必须在二到二十个字符之间。密码长度必须在六到五十个字符之间。密码在存储前进行加密处理。注册成功后自动创建用户会话。

### 2.2 用户登录接口

**接口描述**：验证用户身份，创建用户会话。

| 参数名 | 类型 | 必填 | 说明 |

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| success | 布尔值 | 是否成功 |
| user | 对象 | 用户信息，包含用户ID、用户名、时间限制等 |
| message | 字符串 | 提示信息 |

**成功响应示例**：

**失败响应示例**：

用户名或密码错误时，返回状态码为失败，消息字段提示用户名或密码错误。不明确指出是用户名错误还是密码错误，防止恶意枚举用户名。

**业务规则**：

验证用户名是否存在。验证密码是否正确。登录成功后更新用户的最后登录时间。返回的用户信息不包含密码字段。
