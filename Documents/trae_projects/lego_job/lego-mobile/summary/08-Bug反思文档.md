# Bug反思文档

## 一、概述

本文档基于LEGO Story APP的Git提交历史，记录实际开发过程中遇到的Bug、问题分析和解决方案，帮助团队从实际案例中学习和改进。

## 二、Bug案例详细分析

### 2.1 3D卡片点击崩溃问题（提交：23ce59d7）

#### 问题描述

用户在首页点击"3D卡片演示"入口后，应用立即崩溃，无法进入演示界面。

#### 问题表现

- 点击首页的3D卡片入口
- 应用闪退或白屏
- 控制台报错：Element type is invalid

#### 根本原因分析（五问法）

| 层级 | 问题 | 答案 |
|------|------|------|
| 第一问 | 为什么崩溃？ | 导入了不存在的Extrapolate对象 |
| 第二问 | 为什么导入了不存在的对象？ | react-native-reanimated v3移除了Extrapolate |
| 第三问 | 为什么不知道API变化？ | 升级依赖时未查看CHANGELOG |
| 第四问 | 为什么没有测试覆盖？ | 3D卡片演示功能缺少E2E测试 |
| 第五问 | 为什么缺少测试？ | 演示功能被视为非核心功能 |

#### 解决方案

1. 移除所有Extrapolate导入
2. 实现自定义clamp函数替代
3. 更新use3DCard.js、Card3D.js等组件
4. 简化Card3DDemoScreen使用稳定的组件

#### 影响范围

| 文件 | 修改内容 |
|------|----------|
| use3DCard.js | 移除Extrapolate，添加clamp函数 |
| Card3D.js | 更新动画属性 |
| CardDeck3D.js | 修复属性传递 |
| Card3DDemoScreen.js | 简化组件使用 |

#### 预防措施

| 措施 | 具体做法 |
|------|----------|
| 依赖升级检查 | 升级主要依赖前必须查看CHANGELOG |
| 测试覆盖 | 为所有用户可访问的功能添加测试 |
| 错误边界 | 添加组件级错误边界防崩溃扩散 |

### 2.2 Android网络连接和动画问题（提交：1efdba26）

#### 问题描述

Android打包后应用无法连接后端API，部分动画效果导致崩溃。

#### 问题表现

- 登录功能无法使用
- GlowOrbBackground组件崩溃
- 网络请求全部失败

#### 根本原因分析（五问法）

| 层级 | 问题 | 答案 |
|------|------|------|
| 第一问 | 为什么网络请求失败？ | Android默认禁止HTTP明文请求 |
| 第二问 | 为什么动画崩溃？ | Reanimated不支持left/top属性动画 |
| 第三问 | 为什么开发时没发现？ | 开发模式使用不同的网络配置 |
| 第四问 | 为什么属性不支持？ | Reanimated v3对原生属性有限制 |
| 第五问 | 为什么没有提前测试？ | 缺少真机/模拟器打包测试流程 |

#### 解决方案

1. 添加network_security_config.xml允许HTTP
2. 修改GlowOrbBackground使用transform替代left/top
3. 配置API地址为10.0.2.2用于模拟器访问

#### 修改文件

| 文件 | 修改内容 |
|------|----------|
| AndroidManifest.xml | 添加网络安全配置 |
| network_security_config.xml | 新建，允许本地HTTP |
| GlowOrbBackground.js | 改用transform动画 |
| app.json | 配置API地址 |
| client.js | 添加调试日志 |

#### 预防措施

| 措施 | 具体做法 |
|------|----------|
| 打包测试 | 每次发布前必须打包测试 |
| 动画属性检查 | 使用transform替代位置属性 |
| 网络配置 | 提前配置网络安全策略 |

### 2.3 Reanimated动画属性问题（提交：13e517ed）

#### 问题描述

多个组件使用的动画属性不被Reanimated支持，导致运行时错误。

#### 问题表现

- width/height属性动画报错
- opacity动画异常
- shadowOffset动画失败

#### 根本原因分析（五问法）

| 层级 | 问题 | 答案 |
|------|------|------|
| 第一问 | 为什么动画属性报错？ | Reanimated不支持所有CSS属性 |
| 第二问 | 为什么使用了不支持的属性？ | 开发者不熟悉Reanimated限制 |
| 第三问 | 为什么没有文档说明？ | 项目缺少动画开发规范 |
| 第四问 | 为什么没有静态检查？ | 没有配置相关lint规则 |
| 第五问 | 为什么没有代码审查？ | 动画代码审查不够严格 |

#### 解决方案

1. width/height改用scaleX/scaleY
2. opacity改用特定组件属性
3. shadowOffset改用其他阴影方案
4. 添加ESLint检查脚本

#### 修改文件

| 文件 | 修改内容 |
|------|----------|
| WeatherEffectV2.js | 修复SunEffect和RainDrop |
| MagicParticles.js | 修复glowStyle |
| ChapterScreen.js | underlineWidth改用scaleX |
| use3DCard.js | 修复opacity和shadowOffset |
| check-reanimated.js | 新建检查脚本 |

#### 预防措施

| 措施 | 具体做法 |
|------|----------|
| 静态检查 | 添加prebuild脚本检查动画属性 |
| 开发规范 | 建立Reanimated使用规范 |
| 代码审查 | 动画代码必须审查 |

1. StagePreview添加属性兼容函数
2. 支持character_id、characterId、id三种属性名
3. 添加集成测试验证

#### 修改文件

| 文件 | 修改内容 |
|------|----------|
| StagePreview.js | 添加getCharacterId兼容函数 |
| StagePreview.test.js | 添加兼容性测试 |

### 2.5 WeatherEffect组件children问题（提交：d9a9fea0）

#### 问题描述

舞台预览中的天气效果组件没有渲染子元素，导致角色不显示。

#### 问题表现

- 有天气效果时角色消失
- 无天气效果时角色正常显示
- 组件本身无报错

#### 根本原因分析（五问法）

| 层级 | 问题 | 答案 |
|------|------|------|
| 第一问 | 为什么角色不显示？ | WeatherEffect没有渲染children |
| 第二问 | 为什么没渲染children？ | 组件忘记接收和渲染children参数 |
| 第三问 | 为什么会忘记？ | 组件设计时未考虑包裹场景 |
| 第四问 | 为什么没有类型检查？ | 项目未使用TypeScript |
| 第五问 | 为什么测试没发现？ | 单独测试了组件，未测试组合场景 |

#### 解决方案

1. WeatherEffect添加children参数
2. 添加wrapper样式确保布局正确

#### 预防措施

| 措施 | 具体做法 |
|------|----------|
| 组件规范 | 容器组件必须支持children |
| 组合测试 | 测试组件组合使用场景 |
| TypeScript | 引入类型检查 |

## 六、经验教训

### 6.1 技术经验

1. **依赖升级**：必须查看CHANGELOG，了解Breaking Changes
2. **动画开发**：优先使用transform，避免直接动画位置属性
3. **属性命名**：统一使用驼峰命名，保持一致性
4. **组件设计**：容器组件必须支持children

### 6.2 测试经验

1. **测试数据**：必须使用真实数据结构
2. **组合测试**：测试组件组合使用场景
3. **打包测试**：发布前必须打包验证
4. **多平台测试**：Android和iOS都要测试

### 6.3 流程经验

1. **代码审查**：重点关注接口和属性命名
2. **文档同步**：接口变更及时更新文档
3. **问题记录**：详细记录问题和解决方案
